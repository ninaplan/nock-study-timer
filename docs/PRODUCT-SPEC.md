# 제품 스펙 — 시간표 · 계획/실제 그리드

이 문서는 **시간표(타임블록)**, **템플릿 티어(무료·라이트 vs 프로)**, **구독 기능** 관련 합의를 한곳에 둔다.

## 1. 템플릿 티어와 노션

| 티어 | 노션 시간표 | 앱에서의 날짜 |
|------|----------------|---------------|
| **무료·라이트** | 날짜 없는 **마스터** (매일 같은 슬롯 구조) | **뷰 날짜**로 해석. 하루 경계에 맞춰 **앱 쪽 배정만** 비움. 노션은 **「노션으로 보내기」**로 반영. |
| **프로** | **날짜별 행**; 노션에서 **새로 생성**으로 그날 표를 만듦. 요일은 **날짜 + 노션 수식**으로 충분. | 선택한 **날짜**에 맞춰 읽기/쓰기. |

- **다대다**: 슬롯(시) ↔ 할 일 — 노션에 이미 양쪽 DB **다대다**로 설계. **같은 시 + 같은 할 일** 중복은 **불가**.
- **가져오기 / 보내기**: 편집 위치(앱 vs 노션)는 사용자 취향 → **노션에서 가져오기**, **노션으로 보내기**로 양방향.
- **계정·멀티 워크스페이스**: **계정 추가** 기능 전까지 **한 번에 하나의 템플릿**만 가정.

## 2. 모드 감지

- **자동 감지** 선호: 구현 난이도·오류율·부하가 수용 범위면 (예: 시간표 DB에 **날짜** 타입 필드 존재 여부). 애매하면 **한 번만 사용자 확인** 폴백.
- **충돌 시**: **최근 수정 시각** 우선(Notion `last_edited_time` 등). 불가능하면 **사용자가 선택**.

## 3. 구독·과거 기록 (계획)

- **과거 “계획만” 스냅샷**만 쌓는 것보다, **타이머 앱**에 맞게 **실제 집중**을 보여 주는 쪽이 핵심 가치.
- **확정 방향**: **한 그리드**에 **계획 + 실제**를 **같이** 보여 준다.

### 3.1 시각 규칙 (합의)

- **계획(시간표)**: 옅은 색 / 테두리 / 반투명 등으로 “넣어 둔 블록”.
- **실제(집중)**: 더 진한 채움, 세션 구간에 맞게 색칠(히트맵·블록).
- **같은 날·같은 시간 축**에 겹쳐 그려 **한눈에 대비** (계획 vs 실제).

### 3.2 데이터

- **계획**: 당일/선택일의 시간표 배정(가져온 노션 + 앱 편집, 필요 시 **날짜별 스냅샷**).
- **실제**: 앱 **세션/타이머 로그** (`nock_session_log` 등)를 **날짜·시(·분) 축**으로 집계.

### 3.3 구현 백로그(체크리스트)

- [ ] Log(또는 전용 뷰)에 **일 단위 그리드**: Y축 시간(또는 슬롯), **계획 레이어 + 실제 레이어**.
- [ ] **무료·라이트** 뷰: 마스터 시간표 + 당일 스냅샷/세션을 동일 축에 매핑.
- [ ] **프로** 뷰: 선택 **날짜**의 슬롯 행 + 그날 세션.
- [ ] (구독 시) **지난 날** 그리드 열람 — **계획·실제** 동일 규칙 유지.

## 4. DB 지정 라벨 · 자동 매칭 (앱 UI·휴리스틱)

- **DB 라벨 (기본 한국어)**: 할 일 / 리포트 / 목표 / 시간표 · 영어 UI에서는 **To-do**, **Report**, **Goal**, **Timetable** (단어 첫 글자 대문자).
- **할 일 DB 이름 자동 후보**: `To-do`, `할 일`, `투두` 등 (코드: `Onboarding.js` 등).
- **데일리 리포트 DB**: `Daily Report`, `데일리 리포트` 등.
- **목표 DB**: `Goal`, `Goal Tracker`, `목표` 등 (`notionGoalDb.js`).
- **시간표 DB**: 이름만으로 앱에서 별도 DB를 고르지는 않고, **할 일 DB의「시간표」속성**이 **relation**이면 상대 DB가 시간표(슬롯) DB로 취급된다.

### 4.1 할 일 DB — 속성 UI 라벨 / 자동매칭 별칭 (요약)

- **UI 라벨 (한국어)**: 이름 · 날짜 · 완료 · **집중시간** · **목표** · **시간표** (앱 `i18n` + 온보딩 자동매칭).
- **집중시간(누적) 매핑 후보**: `누적(분)`, `집중시간`, `Focus`, `Focus Time` 등.
- **목표 매핑 후보**: `목표`, `목표 연결`, `Goal`, `Goal link` 등.
- **시간표(타임블록) 매핑 후보**: `시간표`, `Timetable`, `타임박싱`, `타임블로킹`, `Time block(s)` 등 — **rich_text**(시간 인덱스) 또는 **relation**(슬롯 DB).

### 4.2 데일리 리포트 — 속성 매핑 후보 (기존 라벨 유지, 별칭만 확장)

- **리뷰**: `하루 리뷰`, `한줄 리뷰`, `회고` …
- **집중 합계**: `집중 합계`, `하루 집중 합계` …

## 5. 「시간표」DB에 필요한 속성 (슬롯 DB)

앱이 **relation**으로 연결하는 **시간표(슬롯) DB**는 다음을 만족하면 동작한다.

1. **행(페이지) = 1시간 슬롯**  
   - 각 페이지에 **제목(title)** 이 있고, `06 AM`, `14시`, `오후 3시` 등 **시각이 제목에서 파싱** 가능해야 한다 (`timeblockRelation.js`의 `parseHourFromTimeblockTitle`). **0–23**에 대응하는 슬롯이 있으면 앱이 그 시와 매칭한다.
2. **(선택) 프로·다대다**  
   - 슬롯 페이지에 **할 일 DB로의 relation**이 있으면, 그 관계로 “이 시에 어떤 할 일”을 읽고/쓴다. **텍스트-only(라이트)** 는 할 일 쪽 **시간표** 필드에만 써도 된다.
3. **(선택) 날짜·요일**  
   - 프리/라이트 **마스터** 슬롯 DB에는 **날짜가 없을 수 있음**. 프로 **날짜별 행**은 노션 쪽에서 날짜·요일(수식)을 두는 정책.

**정리**: 최소는 **시간이 드러나는 제목**인 행들; 확장은 **할 일 relation**(및 템플릿에 맞는 추가 속성).
